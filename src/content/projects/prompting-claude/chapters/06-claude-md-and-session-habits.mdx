## CLAUDE.md: only what Claude cannot work out

[CLAUDE.md](glossary:claude-md) is read at the start of every session, so every line costs space in the [context window](glossary:context-window).

**Put in:** commands Claude could not guess, style rules that differ from the usual, the test runner, repo etiquette, architecture decisions, environment quirks and gotchas.

**Leave out:** anything Claude can read from the code, long tutorials, and file-by-file maps.

Ask of each line: would removing this cause a mistake? A bloated file gets ignored, so use the word IMPORTANT on at most one or two lines. For rules that must always happen, use a [hook](glossary:hook), because CLAUDE.md is only advice.

## Manage the session

- `/clear` between unrelated tasks.
- Corrected the same thing twice? `/clear` and restart with a better prompt.
- `Esc` interrupts. `Esc Esc` or `/rewind` goes back. Trying something risky is cheap.
- Use a [subagent](glossary:subagent) for investigation, so file reading stays out of your main session.
- Ask a second session or subagent to review the change against your spec, with fresh eyes. That is the same idea as a [code review](glossary:code-review).

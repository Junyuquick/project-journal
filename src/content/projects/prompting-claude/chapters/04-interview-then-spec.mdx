For a whole app or a large feature, you do not yet know everything you want, and neither does Claude. The fix is to let Claude interview you.

## The interview prompt

> I want to build [brief description]. Interview me in detail, one topic at a time: users, core flows, data, edge cases, stack, UI, what is out of scope. Then write SPEC.md with a final end-to-end verification step.

Claude asks, you answer, and the answers become a [spec](glossary:spec): a written description of what to build.

## What a strong spec contains

- The files and interfaces involved, by name.
- What is **out of scope**, so Claude does not add extras.
- A last step that proves the whole thing works from start to finish.

## Build in a fresh session

Once SPEC.md exists, start a new session and tell Claude to read it. The interview used up a lot of the [context window](glossary:context-window), and a fresh start gives Claude room. The spec is also the written source of truth, so you and Claude cannot quietly drift apart later. This is the same idea as an [implementation plan](glossary:implementation-plan), written before the work starts.
